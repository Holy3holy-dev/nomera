# fix: безопасный первый этап H3H Nomera — гонки, сохранения и PWA

Base: `main` (`6489745c063f50ee6492e3382bdb22e46e9e066a`).
Head: `dev/first-safe-hardening`.

Гонки показывали XP, не начисляя его, сохраняли скорость аварии вместо максимальной и отправляли
устаревшие рекорды в облако. PWA не регистрировался и мог удерживать старый HTML. Клиент также содержал
публичный привилегированный обход и страницу просмотра PIN.

## Изменения

- Удалены публичный admin credential, автоматическое повышение роли/баланса/уровня и просмотр PIN.
  Привилегированные операции временно заблокированы до серверной проверки; старые данные не удалены.
- Исправлены числовой XP гонки, peak speed, сохранение рекордов до account snapshot, повторное завершение заезда.
- Рекорды изолированы по аккаунтам. v1 сохранён и импортируется только для установленного владельца старого локального save.
- Облачный профиль и leaderboard сохраняются одним multipath update через последовательную очередь;
  неизвестные поля профиля сохраняются. Ошибки storage и неподтверждённые saves показаны в статусе.
- Защита от поздней загрузки облака после местного действия/смены аккаунта; пустые гаражи сохраняются пустыми.
- Выигрыш кейса можно получить один раз. Замена номера возвращает предыдущий, устаревшие индексы проверяются.
- Экранирование HTML/JS контекстов, проверка URL аватаров/картинок, доверенные стили редкости и проверка лотов.
- Небезопасная смена ключа nickname временно блокируется, редактирование аватара остаётся доступным.
- Pointer capture и сброс педалей при потере фокуса, отмене касания и рестарте.
- PWA: имя/локальные иконки, регистрация, versions ресурсов, очистка только собственных кэшей,
  offline shell и ожидание закрытия старых вкладок перед активацией.
- HTML/CSS вынесены из монолита; modules security/storage/race records, одна canonical game вместо test.html duplicate.
- Node tests и CI без новых runtime dependencies. Локальный PowerShell сервер ограничен корнем.
- Аудит, server-authoritative economy design, атомарный market protocol, этапы migration PIN и недеплоимый проект staging rules.

## Проверка

Выполнены `npm run check` и `npm test`: **22 теста прошли**.
Тесты используют Node VM, mock DOM, synthetic storage и mock Firebase/SW; продуктивные запросы не выполняются.
Проверены syntax, asset links и hashes, role quarantine, numeric XP/peak/settlement, account isolation,
legacy records, storage failure, save order/retry, stale hydration, reward claims, XSS contexts и worker scope.

**Не проверено:** визуальное отображение и реальная гонка в Chrome/Android, настоящая установка PWA,
Firebase Auth/RTDB emulator rules и сетевая интеграция staging. В среде нет Chromium; попытка загрузки
browser binary вернула непригодный архив. PowerShell отсутствует, изменение serve.ps1 проверено чтением кода.
Перед merge/release требуются desktop/mobile smoke tests и проверка legacy sync на staging.

## Риски / дальнейшие действия

- Это не завершённая защита Firebase. Legacy PIN и прямые записи экономики/рынка остаются.
- Существующий `database.rules.json` не изменён: развёртывание строгих правил сейчас отключит legacy игроков.
- Старый публичный пароль в Git history остаётся скомпрометированным: нужен отдельный подтверждённый отзыв/ротация.
- Нельзя включать v2 rules до backend migration; рабочая база, пользователи и баланс не мигрировались.
- Client queue не решает stale balances между вкладками и race conditions рынка; необходим серверный transaction.
- Temporary quarantine admin/rename — осознанное ограничение до backend, UI hooks сохранены.
- Публиковать весь HTML/CSS/JS одним релизом; обновление PWA не прерывает существующий заезд.

Не merging main, не deploying, не запускать миграцию без отдельного подтверждения владельца.
