## Звук

Отдельный `js/audio.js` на Web Audio API, без новых runtime dependencies и внешних аудиофайлов.
Мягкий click/tick, двухслойная фиксация символов, денежная награда, джинглы редкости,
сигнал старта, авария и стилизованный двигатель. Двигатель меняет высоту/фильтр при скорости, газе и нитро;
это синтезированный игровой звук, а не реальная запись конкретной модели автомобиля.

AudioContext создаётся только после жеста пользователя. Модуль выдерживает отсутствие API,
запрещённый resume и повреждённые параметры; звук не прерывает игровую логику.
Умеренный master gain, лимит simultaneous voices и cooldown tick.
Engine nodes создаются один раз на заезд и освобождаются при остановке, mute/engine-off,
скрытии страницы или потере фокуса. Возврат звука — после нового пользовательского взаимодействия.
Настройки volume/mute/engine живут в отдельном `nomera_audio_v2`, не меняя формат прогресса.

## Проверка

- `npm run check`: syntax, asset links/hashes и ранее добавленные security checks.
- `npm test`: **27 тестов прошли**. Пять новых тестов проверяют lazy audio,
  API failures, mute/engine cleanup, изменение engine pitch и background suspension.
- `npm run test:browser`: локальный Chromium, 1366×1000 / 390×844 / 320×740.
  Все семь вкладок, start/exit race, отсутствие page errors и горизонтального переполнения,
  сохранение sound preferences после reload. Рендеры desktop/mobile визуально просмотрены.
- В browser runner заблокированы все внешние запросы, включая Firebase; production reads/writes не выполнялись.
  PWA в браузерном smoke заблокирован, worker semantics проверены Node tests.

Ограничения: headless Chromium не заменяет физическое Android/iOS устройство и субъективное прослушивание.
Реальные Safari audio policies, установку PWA и live Firebase integration нужно отдельно проверить перед публикацией.
Онлайн Firebase safety ограничения первого этапа сохраняются; этот этап посвящён UI/аудио.
