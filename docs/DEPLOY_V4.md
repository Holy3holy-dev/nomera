# H3H Nomera V4: Firebase + Netlify Admin

## Что уже есть в проекте

- Firebase Realtime Database `bazanomerann` уже подключена клиентом для пользователей, чата, рынка, лидерборда, активности. **Это legacy-схема с открытыми правилами и PIN в открытом виде.** Не путать её с защищённой системой управления.
- Новая Netlify Function `netlify/functions/admin.js` выполняет админ-действия только после серверной проверки логина `h3h` и пароля (scrypt-хэш в переменной окружения).
- Сессия хранится только в `HttpOnly Secure SameSite=Strict` cookie с HMAC-подписью, срок 2 часа, нет клиентского пароля/ключа Firebase Admin.
- Все административные операции записываются в отдельный закрытый узел `adminAudit`.
- Лимит попыток входа: 5 за 15 минут на IP (через Firebase transaction в `adminSecurity`).
- Чтение админом списка игроков ограничено 200 записями, журнала — 150.

## Настройка переменных Netlify

В [Netlify](https://app.netlify.com) → проект `nomera1` → **Project configuration / Environment variables** добавьте (область Functions):

| Переменная | Значение |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT_JSON` | **Полное содержимое** скачанного JSON Firebase Service Account, одной строкой. Хранить только в переменных окружения Netlify, никогда в ZIP, GitHub или JS браузера. |
| `FIREBASE_DATABASE_URL` | `https://bazanomerann-default-rtdb.europe-west1.firebasedatabase.app` (опционально, совпадает с настройками текущего проекта) |
| `NOMERA_ADMIN_PASSWORD_HASH` | Результат `npm run admin:hash` при временной переменной `NOMERA_ADMIN_PASSWORD` с выбранным владельцем паролем (не записывайте его в репозиторий). |
| `NOMERA_ADMIN_SESSION_SECRET` | Случайная секретная строка минимум 32 байта, например результат `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`. |

Чтобы получить хэш **локально** на компьютере, в PowerShell выполните:

```powershell
$env:NOMERA_ADMIN_PASSWORD = Read-Host 'Пароль администратора'
npm run admin:hash
Remove-Item Env:\NOMERA_ADMIN_PASSWORD
```

Скопируйте полученную строку `scrypt$...` в `NOMERA_ADMIN_PASSWORD_HASH`. Не вводите пароль прямо в команду: он может попасть в историю терминала.

## Как опубликовать

Для полноценного админ-режима необходимо, чтобы **Netlify Functions были собраны и опубликованы**.

1. Рекомендуемый путь: разместить содержимое папки `H3H_Nomera_Codex` в GitHub и подключить репозиторий как источник деплоя к Netlify `nomera1`; build settings: publish directory `dist`; Netlify установит зависимость `firebase-admin` из `package.json` и соберёт функцию.
2. Альтернатива: Netlify CLI с установленными npm-зависимостями, `npm run build`, затем `npx netlify deploy --prod --dir dist --functions netlify/functions --site <ID_ВАШЕГО_САЙТА>`; убедитесь, что публикация включает функцию. Не добавляйте секреты в команду.
3. Просто перетащить статический ZIP в Netlify Drop **недостаточно для гарантированного развёртывания серверных функций**; тогда игра будет работать, но защищённая админка выдаст сообщение о недоступном сервере.
4. После развёртывания откройте игру → **Профиль → Вход** → `h3h` и пароль; проверьте вкладку администрирования, список пользователей, журнал и операции на отдельном тестовом профиле.

Не нужно заводить ещё один Firebase-проект: новая серверная функция использует **текущий** `bazanomerann` при условии, что сервисный JSON выдан именно для этого проекта.

## Существенные ограничения безопасности

Новые admin endpoints защищены, **но игровая экономика пока не является сервер-авторитетной**. Текущая версия клиента по-прежнему может писать `users`, `market`, `chat`, `leaderboard` в старую Firebase Realtime Database, что позволяет клиенту подменить баланс и перезаписать изменения администратора. Legacy аккаунты используют PIN в незашифрованной записи. **Не выдавать эту версию за защищённый коммерческий сервис** и не использовать с реальными деньгами.

Для полноценной защиты надо мигрировать игроков на Firebase Authentication, хранить приватные аккаунты на сервере, проводить открытие кейсов/спины/покупки/торговлю атомарными серверными транзакциями и затем включить правила из `docs/database.v2.staging.rules.json` после staging-миграции. Не включайте их на production немедленно: это сломает старую игру. Перед любыми изменениями правил сделайте резервную копию Firebase.

```
npm run assets
npm run check
npm test
```

Новые настройки сервера не проверяются из offline ZIP; необходимо тестировать после deployment в Netlify с вашим Firebase. Не передавайте сервисный JSON в чат или публичный репозиторий.
