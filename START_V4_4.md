# H3H Nomera V4.4 Online — тестовый выпуск

Выпуск основан на V4.3.2. **Предназначен для владельца проекта и тестирования**, не является готовой публичной экономикой.

## Что работает

- Modern Netlify Function `online.mjs`: HTTP-only сессия игрока, PIN в salted `scrypt` на сервере.
- Однократный перенос **одного существующего тестового аккаунта** через подтверждённую админскую сессию. Браузер НЕ может самостоятельно выдать себе баланс через онлайн API.
- Онлайн-рынок: выставление, покупка, отмена. Все деньги/лоты/инвентарь находятся в `onlineV4` и изменяются **одной Firebase Realtime Database транзакцией**. Повторная покупка не выдаёт номер повторно.
- Чат: сервер проверяет вход, имя отправителя, длину и 3-секундный интервал. Обновление раз в 12 секунд, не WebSocket.
- Админские корректировки баланса, выдача номеров и машин учитывают новый онлайн-профиль и сохраняют зеркальные данные в старом `users` для совместимости.
- Клиент более не пишет `users`, `market` или `chat` напрямую в Firebase.

## Важные ограничения

- **Старые генератор, кейсы, гонки, тюнинг и локальная продажа** продолжают работать на устройстве. До серверной миграции этих механик награды не могут безопасно пополнять онлайн-кошелёк.
- Онлайн-инвентарь содержит только номера, подтверждённые при однократной активации / выданные сервером / приобретённые на рынке. Новые локальные выигрыши НЕ становятся автоматически торгуемыми.
- Облако гарантирует только новый онлайн-кошелёк/рынок/чат; локальные гараж, тюнинг, награды гонок пока не синхронизируются между устройствами. Ни в коем случае не очищайте данные браузера.
- Это тестовая схема с транзакцией над всем `onlineV4`, пригодна для небольшого числа аккаунтов. Перед большим запуском понадобится индексирование, постраничный просмотр и перенос всей экономики на сервер.
- Регистрация новых обычных игроков не открыта: стартовые профили создаёт/мигрирует администратор. Старый PIN игрового профиля отличается от нового онлайн PIN.
- Открытые на прошлых версиях пути `market` и `chat` не используются. Старые объявления/сообщения не мигрируют; аккаунты и состояние `users` остаются нетронутыми.

## Перед первым переносом

1. В Firebase Console `h3h-nomera-server` → Realtime Database → вкладка **Data** → экспорт JSON резервной копии. Храните копию приватно. **Не удаляйте базу и локальное сохранение браузера.**
2. Убедитесь, что деньги, гараж и номера видны в **V4.3.2 на том же телефоне**. Первый перенос захватывает данные, доступные в локальном профиле, а для баланса приоритет имеет серверная запись `users/<nick>/balance`.
3. Сначала публикуйте **Draft deploy**, не `--prod`. В проекте Netlify уже должны быть `FIREBASE_SERVICE_ACCOUNT_JSON`, `FIREBASE_DATABASE_URL`, `NOMERA_ADMIN_SESSION_SECRET`, `NOMERA_ADMIN_PASSWORD_HASH`, `NOMERA_FIREBASE_WEB_CONFIG`.
4. Netlify CLI из Termux (в директории проекта):

```sh
unzip -o ~/storage/downloads/H3H_Nomera_V4_4_Online_Beta.zip -d ~/h3h-deploy
cd ~/h3h-deploy/H3H_Nomera_Codex
npm test
npm run build
netlify deploy --no-build
```

5. Если нет ошибок, откройте **тестовый Deploy URL**. Войдите в **тот же локальный игровой профиль**, где хранятся номера.
6. Войдите в админку под `h3h` через существующую форму. Вкладка «Онлайн» → **«Вход / перенос»** → укажите **новый PIN длиной от 6 символов** → **«Первый перенос (админ)»**. Сначала сверьте сохранённую копию и подтверждение в интерфейсе. Не сообщайте PIN никому.
7. После активации повторная активация запрещена: используйте кнопку **«Войти»**, не «Первый перенос». PIN хранится на сервере как `scrypt`-хэш; пароль администратора остаётся отдельно.
8. Для теста выставьте один недорогой номер; снимите лот с продажи; напишите сообщение; обновите страницу и нажмите `↻ Кошелёк`.
9. Только после проверки публикуйте: `netlify deploy --no-build --prod`.

## Firebase Rules

Серверу используется Firebase Admin SDK, который не зависит от клиентских правил. Во вкладке **Realtime Database → Rules** безопасный итоговый вариант — содержимое `database.rules.json`: чтение и запись для браузерных Firebase SDK запрещены, включая `onlineV4`. База доступна только доверенным серверным функциям. Перенастройка Rules нужна только когда будет принято решение закрыть старые публичные пути.

## Если что-то не заработало

- `/.netlify/functions/online?action=public` должно вернуть JSON с `ok:true`. Ответ `404` — функция не опубликована. `503` — нет корректных секретов. Ошибка 400 — проверяйте логи Functions.
- Если нет кнопки «Первый перенос» / не работает админский билет — убедитесь, что вошли в админку на **том же draft-домене**.
- Если число денег отличается: на переносе серверный `users/<nick>/balance` важнее локального значения (это защищает от подделки). При необходимости исправьте существующий серверный баланс через админку **перед** переносом.
- Если админ после переноса выдал деньги/номер, нажмите **«↻ Кошелёк»**, чтобы обновить онлайн-данные.
- Не присылайте приватные ключи и токены. Для диагностики достаточно скриншота ошибки без секретов.
